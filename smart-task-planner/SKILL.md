# Smart Task Planner

## 1. 目标

将用户的自然语言任务描述转化为结构化任务，并通过 `scripts/task_planner.py` 中的独立 Python 函数管理任务数据。

Agent 负责：
- 理解用户目标和约束。
- 将复杂目标拆解成可执行任务。
- 识别依赖关系、优先级和时间要求。
- 决定调用哪些工具以及调用顺序。
- 根据工具真实返回值向用户展示计划。

Python 脚本负责：
- 校验参数。
- 计算截止时间。
- 保存、查询和更新任务。
- 检查任务时间冲突。
- 汇总任务状态和完成情况。

本 Skill 不需要网络、文件上传或第三方 Python 依赖。

## 2. 工具脚本

脚本位置：`scripts/task_planner.py`

建议由宿主 Agent 将以下函数注册为工具。函数都在同一个 Python 脚本中，但保持独立、可单独调用。

### `create_task(...)`

创建并持久化一条任务。

参数：
- `title`：任务名称，必填。
- `description`：任务描述。
- `priority`：`high`、`medium` 或 `low`，默认 `medium`。
- `start_at`：计划开始时间，ISO 8601 字符串，例如 `2026-11-02T09:00:00`。
- `end_at`：计划结束时间，ISO 8601 字符串；如果省略但提供 `start_at` 和 `estimated_hours`，脚本会自动计算。
- `deadline`：截止时间或日期，例如 `2026-11-06T18:00:00`。
- `estimated_hours`：预计耗时，正数。
- `status`：`todo`、`in_progress`、`done` 或 `cancelled`，默认 `todo`。
- `dependencies`：依赖任务 ID 列表。先创建前置任务，再把工具返回的 ID 传给后续任务。
- `tags`：字符串标签列表。
- `store_path`：可选任务数据文件路径；不传时使用 `TASK_PLANNER_STORE` 环境变量，默认 `./data/tasks.json`。

成功时返回 `{"status":"success","task":{...}}`。

### `calculate_deadline(start_at, duration, unit="hours", working_days_only=False, holidays=None)`

根据开始时间和持续时间计算结束/截止时间。

- `unit="hours"`：按小时增加。
- `unit="calendar_days"`：按自然日增加。
- `unit="working_days"`：按工作日增加，跳过周六、周日和 `holidays` 中的日期。
- `holidays`：日期字符串列表，例如 `["2026-11-11"]`。
- `duration` 必须大于 0；工作日模式要求整数天数。

成功时返回开始时间、持续时间、单位和计算结果 `deadline`。

注意：`calculate_deadline()` 只负责计算，不会自动创建或保存任务。

### `check_conflicts(task_id=None, store_path=None)`

检查任务日程冲突。

- 不传 `task_id`：检查所有未完成、未取消任务之间的两两冲突。
- 传入 `task_id`：只检查该任务与其他有效任务的冲突。
- 只有同时具有 `start_at` 和 `end_at` 的任务参与日程冲突检查。
- 时间区间采用左闭右开逻辑；一个任务 09:00–10:00，另一个任务 10:00–11:00，不算冲突。
- 已完成和已取消任务不参与冲突检查。

成功时返回冲突数量和冲突任务对。

### `summarize_tasks(store_path=None, as_of=None)`

统计任务情况：
- 任务总数。
- 各状态数量。
- 各优先级数量。
- 已完成数量和完成率。
- 逾期未完成任务数量及 ID。
- 最近截止任务。

`as_of` 可选，使用 ISO 8601 日期/时间；不传时使用当前本地时间。

### 辅助函数

- `list_tasks(status=None, priority=None, store_path=None)`：查询任务，可按状态和优先级筛选。
- `update_task(task_id, ..., store_path=None)`：修改任务标题、描述、优先级、时间、预计耗时、状态、依赖和标签。

## 3. 时间与优先级规则

1. 时间统一使用 ISO 8601 格式。没有时区信息时，视为用户当前使用的本地时间；同一任务库内不要混用带时区和不带时区的时间。
2. 用户说“明天”“下周五”等相对日期时，先确认系统当前日期和用户时区；无法确定时，向用户询问，不要猜测。
3. 用户明确给出截止日期时，必须保留该截止日期，不得擅自延后。
4. 用户没有给出开始时间或截止时间时，不要擅自编造精确时间。可以创建不带排期的任务，或询问必要信息。
5. 优先级含义：
   - `high`：紧急、重要、临近截止或阻塞其他任务。
   - `medium`：正常推进、重要但不紧急。
   - `low`：可延后、非关键或可选事项。
6. 依赖任务必须先创建。使用前置任务实际返回的 `task_id` 填入 `dependencies`，不得自行编造 ID。
7. 冲突检测只报告冲突，不自动移动或覆盖用户安排。先给出调整建议，等待用户同意后再调用 `update_task()` 修改。
8. 不得把“预计耗时”误当作“截止日期”。有开始时间和预计耗时时，可以调用 `calculate_deadline()` 推算计划结束时间；最终截止时间仍以用户明确要求为准。

## 4. 推荐工作流

用户要求规划一组新任务时：

1. 提取项目目标、任务内容、截止日期、可用时间、预计耗时和优先级。
2. 将目标拆分为粒度合理、可执行的子任务。
3. 识别任务依赖，先创建没有前置依赖的任务。
4. 对有开始时间和预计耗时的任务，调用 `calculate_deadline()` 计算计划结束时间。
5. 调用 `create_task()` 保存任务。把前置任务实际返回的 ID 传给依赖任务。
6. 所有任务创建完成后，调用 `check_conflicts()`。
7. 调用 `summarize_tasks()` 获取整体统计。
8. 向用户展示任务列表、优先级、排期、依赖、冲突和统计结果。

用户只要求查看现有任务时，先调用 `list_tasks()`，不要重复创建任务。

用户要求修改任务时，先查询任务并确认目标 ID，再调用 `update_task()`。

## 5. 输出格式

规划完成后，使用表格呈现：

| 任务 | 优先级 | 开始时间 | 计划结束 | 截止时间 | 状态 | 前置任务 |
|---|---|---|---|---|---|---|

随后说明：
- 任务拆解逻辑。
- 时间冲突及涉及的任务。
- 需要用户确认的排期调整建议。
- 任务总数、完成率、逾期数量和优先级分布。

所有 ID、日期、统计数字和冲突信息必须来自工具真实返回结果。不得声称已保存或修改任务，除非工具返回成功。
